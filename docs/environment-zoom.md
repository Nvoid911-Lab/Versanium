# モバイル／DeX別ズーム

作業元は `feature/f11-toolbar` の `a5909598c55da64751d70a8d2facf4a555eab554`。
作業ブランチは `feature/dex-mobile-zoom`。本家・コピー元・main・F11ブランチへの変更はない。

## 設定と保存

設定 → ユーザー補助に、モバイルとDeX／外部画面のデフォルト倍率（50～300％、1％刻み）、
この画面の判定の補正、環境別の保存済みサイト一覧を用意する。
従来のグローバルズーム操作・旧サイト一覧はこの画面から置き換え、サイト設定の旧Zoom一覧も非表示にする。
他のユーザー補助設定と、Smart Zoomが有効な場合の既存テキストコントラスト設定・プレビューは保持する。

保存先はプロフィールのパスから作った名前の専用SharedPreferences。
値は絶対倍率の指数で、Mobile／DeXのデフォルトとサイト辞書を分ける。
現在の環境のサイト別値があればそれを使い、なければその環境のデフォルトを使う。
デフォルト変更は辞書を削除・書き換えない。明示的な100％等はデフォルトと一致していても残る。
スライダー、±、ネイティブのキーボードズームは操作したActivityの環境だけに保存する。

サイト設定の解除は、ズームバーのReset、またはユーザー補助の該当環境のサイト一覧でサイトを選びReset。
前者は現在の環境のみ、後者は選択した一覧の環境のみ。デフォルトと同じ値を選択することは解除ではない。
LFFのメニューにResetがない場合も設定画面の一覧から解除できる。

初回だけ、Chromiumの旧ホスト辞書を両環境へコピーする。
新規プロフィールはモバイル100％／DeX67％。
旧デフォルトが保存済み（100％を含む）、旧デフォルトが非100％、または旧サイト辞書が存在する場合は、
両環境のデフォルトを旧値にする。Androidの `partition.default_zoom_level.android` の保存有無も調べる。
このため既存プロフィールではDeXの初期値が67％とは限らない。設定画面で変更できる。
マーカーと両辞書をworker上の一つのcommitで保存し、保存成功後の再起動・更新では再移行しない。UI操作は200msでまとめ、同期commitでUIを待たせない。保存失敗・保存前の強制終了の制約は統合レビューを参照。
旧Chromiumのデータは消去・変更しない。旧処理が既に消していた明示的な同値設定は復元できない。

シークレットは通常プロフィールの最新メモリ値（通常プロフィールが未ロードなら保存値）から始まるメモリ内スナップショットを使用し、
閲覧先と倍率変更をディスクに書かない。OffTheRecordProfileImplのGetPathは通常プロフィールと同じなので
読み取りだけ共有し、書き込みはIsOffTheRecordで遮断する。プロフィール破棄時にスナップショットと紐付けを破棄する。
別のシークレットプロフィールは別ストアになる。実APKでのプロフィール／設定画面の接続確認は別途必要。

## 倍率とホスト単位

調査対象Chromiumは `155.0.8059.39`。Blinkは `倍率 = 1.2^指数`。
元の67％プリセットは指数-2.20なので約66.9578128％（UIは67％）。
新設定は `log(0.67)/log(1.2) = -2.1965453435092885` を丸めずに保存し、約67.0000000％を適用する。
スライダーと新設定は整数百分率から計算し、旧プリセットからのページ操作も表示整数に正規化する。
移行した旧倍率は丸め直さない。ユーザーが明示的に変更するまで旧値を保持する。

ホストキーはネイティブの `net::GetHostOrSpecFromURL` に揃える。
パスやポートでは分けず、HTTPとHTTPSの同じホストは共通。`example.com`、`www.example.com`、`m.example.com` は別。
GURLによる正規化後のキーを使い、登録可能ドメインへのまとめは行わない。
ホストのないURLではChromiumと同じくURL specを使う。通常プロフィールのサイト一覧はそれを表示するが、ログには出さない。

## 判定と適用

WebContents → WindowAndroid → Activityと、そのActivityのContextに対応するDisplayAndroidのIDを使う。
自動では組み込み画面（ID 0）はMobile、非0の外部／別画面はDeX。
User-Agent、PC版サイト、ウィンドウ幅や、接続中という端末全体の状態で判定しない。
DeX接続中に本体画面を使うActivityはMobileのまま。

これはSamsungのDeX状態を認証するAPIではなく、公開APIによる外部画面のヒューリスティック。
仮想画面・キャスト等もDeX扱いになり得る。外部画面でもID 0を使うモードは自動では区別できない。
設定の「この画面のズーム環境」で自動／Mobile／DeXを補正できる。
補正はdisplay ID単位で保存するため、再接続・再起動でIDが変わる／再利用される機種では再確認が必要。
自動判定だけでGalaxy S23／One UI 8.5の全モードが確実に判定できるとは主張しない。

プロフィールのHostZoomMapやプロセス全体のデフォルト／外部画面スケールを書き換えない。
WebContents/RFHのズーム照会時に、渡されたRFHのURLと現在のActivityから倍率を返す。
ネイティブのHostZoomMapの読み取り・書き込みと、WebContentsImplのpending navigation/BFCache経路を接続する。
ホスト全体の値を切り替えて二つの画面へ配信する設計ではない。
元のprocess-global transparent adjustmentは使わず、環境の百分率を絶対倍率として適用する。
OS文字倍率を考慮する実験が有効ならActivity側のfontScaleだけを使う（対象ソースの通常設定は無効）。
独立ズームのサブフレームには既存処理を残す。

TabImplのWebContents作成・差し替え／再接続で紐付けを設定し、表示・Activity再開で再適用する。
Activityの構成変更とDisplayManagerの追加・削除・変更通知でも全管理対象を再評価する。
その際も各WebContentsの現在の画面から計算し、保存データは変えない。
ページ遷移、レンダラ差し替え、BFCache、復元はネイティブのズーム取得経路で現在のURLを照会する。
画面移動時のAndroidコールバック順序／通知漏れは実機で確認が必要。

## ローカル検証

以下は実行済み（Chromiumフルビルド、build.sh、Actionsは実行していない）。

- `run_local_tests.py`: 本番Policyの481アサーション。実ファイルの保存・再読み込み、1回の移行、
  明示的な同値設定、デフォルト変更、サイト単位の解除、ホスト／サブドメイン独立、メモリ専用セッションを検証。
- 同じコマンドで本番EnvironmentZoom bridgeの31アサーション。
  Android/JNI/rendererはテストダブル。2画面、構成変更、Activity再生成、環境補正、プロフィール破棄と再読み込みを検証。
  実Androidライフサイクルやネイティブ描画の成功を意味しない。
- `check_patch.py`: 対象ファイルにTitaniumと同じ選択／名称置換でVanadiumパッチを適用し、
  実際のズームパッチ・overlay・XMLを検証。元ソースの前提の変更時に、一切書き換えずに拒否する負の検証も実行。
- 変更後と新規のJavaソースをECJのJava 23構文パーサーで検証。
  既存Chromiumの未使用変数 `_` はJava 21では解析できないのでJava 23を使用。
  Chromium全体のJava型解決・NullAway・GNコンパイルは未実施。後続の統合レビューで実JNI生成と限定C++シグネチャ検証、実Android API相手の限定コンパイルを追加した。全体の型チェックではない。
- `bash -n`、actionlint、git diff --check。

JDK 21以上がある環境で:

```sh
python3 tools/environment_zoom/tests/run_local_tests.py
# javacのない本環境では、MavenのHTTPSと公開チェックサムで検証したECJ 3.40.0を使用:
python3 tools/environment_zoom/tests/run_local_tests.py --ecj /tmp/titanium-zoom/ecj.jar
# 別途用意した固定版の対象ソースを指定（このツールは取得・フルビルドをしない）:
python3 tools/environment_zoom/tests/check_patch.py \
  --source-tree /path/to/chromium-155.0.8059.39 \
  --vanadium-patches /path/to/Vanadium-c1892f4/patches
```

## ビルド前・APKでの確認

パッチ対象はVanadium `c1892f4db7a828b9fcbca9ab6a6898b0a7396fae`、Chromium `155.0.8059.39`。
F11テスト時だけWorkflowのUpdateをスキップしてサブモジュール参照を固定する。
通常ビルドのUpdateとrunner、Secrets、署名処理は保持する。
バージョンを変える場合はまずcheck_patchとAPIの再確認が必要。異なるソースへの暗黙の適用は禁止。

最新の追加検証と修正は [統合レビュー](environment-zoom-integration-review.md) を参照。
この変更はレビュー可能な実装であり、全体のネイティブ／JNI／GNがコンパイル済みのAPKではない。
有料のBlacksmithビルド前に、利用可能な既存ChromiumツリーでGN/JNI生成、Java型チェックと対象C++の
限定コンパイルができるならそれを優先する。本環境にはその生成済みツリーとAndroid実行環境がなく未実施。
これが残る統合検証上のリスク。481＋31の成功だけで実機の準備完了とは判断しない。

APKでは少なくとも以下を確認する:

1. 本体／有線DeXの同時Activityで同じホストに100％／80％を保存し、独立した描画倍率か。
2. DeXデフォルト80％→67％でも明示的80％が残るか。設定と同値の明示100％も維持されるか。
3. Resetが片方だけに作用し、未指定サイトが現在のデフォルトを使うか。
4. 接続・切断、既存の2画面間移動、回転、Activity再生成、タブ復元、別ホスト遷移、BFCache、タブ切替。
5. プロセス終了・再起動、アプリ更新後も移行が繰り返されないか。旧データの倍率が保持されるか。
6. シークレットの変更が通常タブ／ディスクに混ざらず、全シークレット終了後に破棄されるか。
7. F11、共存パッケージとProvider/権限、APK署名が従来通りか。

保存値を切り替えるテストと、画面上の実際の描画倍率のテストを分ける。
内部HTMLページ、PDF、ピンチズームとの関係はChromiumの既存制約もあるので通常HTTP(S)から確認する。
